## 研究问题与主要结果

“抬头、抬手、抬腿”统一表示为：**选择身体连杆上的一个局部点，指定它的目标位置／方向、有效坐标分量及容差，再让全身关节共同寻找动作。** 不同部位共用任务语法和求解流程，实际可达性和支撑条件由结构、状态、动作及接触决定。

| 方法 | 抬高目标成功 | 方向目标成功 |
|---|---:|---:|
| 保持当前关节姿态 | 0/36 | 0/36 |
| 固定基座的 URDF 运动学优化 | 14/36 | 1/36 |
| 目标注意力策略直接输出动作 | 0/36 | 0/36 |
| 无显式接触输入的学习规划 | 13/36 | 4/36 |
| 有接触输入的学习规划 | 12/36 | 13/36 |
| 有接触输入＋省力目标 | 12/36 | 13/36 |

每个方法各做 36 个抬高任务和 36 个方向任务，总计 6 × 72 = **432 个试验**。每类任务只有 6 个初始物理状态，不是 36 个独立随机机器人。成功包含到达和停稳，不能把仅接近目标计为成功。

这组结果的含义：

1. **统一接口已经落实。** 改变目标部位只更换节点编号和目标数据，不换控制函数、网络或动作模板。
2. **学习方案在方向任务中表现更好，但并未全面超过运动学。** 方向任务 13/36 对比运动学 1/36；抬高任务 12/36，反而低于运动学的 14/36。这是整套控制方案的比较，不单独归因于动力学模型。
3. **显式接触信息的收益依赖任务。** 去掉接触输入后方向成功数为 4/36，抬高却为 13/36；不能声称它对所有任务均有收益。
4. **成功仍依赖模型上的动作优化。** 单次网络前向输出动作的策略在两类正式任务中均未达标。它被用作候选动作初值，不能称为已学会直接执行这些技能。
5. **“最省力”尚未得到证明。** 省力目标降低了部分成功任务的实测负担，但没有提高总体成功率，也没有证明比运动学对照更省力或达到全局最优。

### 分身体区域结果

以下为“接触模型＋省力目标”，每格分母为 6 个初始状态：

| 目标区域 | 抬高 25 mm 并停稳 | 改变方向 15° 并停稳 |
|---|---:|---:|
| 基座／骨盆 | 0/6 | 0/6 |
| 头部 | 2/6 | 2/6 |
| 左手 | 6/6 | 6/6 |
| 右手 | 4/6 | 3/6 |
| 左脚 | 0/6 | 2/6 |
| 右脚 | 0/6 | 0/6 |

这里“手”对应腕部连杆，“抬腿”用脚部连杆上的点升高作为可测目标。目标点采用对应连杆的局部质心位置，头部使用 `head_pitch_link`，手部使用 `*_wrist_link`，脚部使用 `*_ankle_roll_link`。接口也接受其他局部点，训练时对局部点加入了小幅随机偏移；本次正式测试没有证明任意身体表面点的泛化。

## 省力的定义与实际效果

主要优化代理为全过程实测的归一化力矩平方积分：

```text
Effort = ∫ Σ_j (tau_actual_j / tau_limit_j)^2 dt
```

同时记录正机械功 `∫Σ max(tau_j * dq_j, 0)dt`、峰值力矩、速度超限比例和软限位穿透。持续承重即使速度为零，力矩平方积分也会增加。它是电机负担代理，**不是测得的耗电量**。

学习规划和省力版使用相同初态、目标与 3.2 s 总时长。只在二者都成功的配对试验中比较用力：

- 抬高任务：8 个共同成功任务，全部为手部任务；实测用力积分相对下降平均 **38.6%**，中位数 39.2%。
- 方向任务：9 个共同成功任务；相对下降平均 **30.1%**，中位数 24.5%。
- 两类任务都各有 4 个“原方法成功、省力版失败”和 4 个“省力版成功、原方法失败”。不能把相同的总成功数理解为相同任务都成功。
- 按初始姿态／种子分组重采样得到的探索性区间见 `summary_test_*.json`。初始状态数和训练种子数都少，这些区间不能代表跨机器人、地面或训练随机性的置信保证。

省力版在优化过程中寻找预测目标误差较小的候选，再比较预测用力。最后报告的是物理执行时测量的用力，不是网络自己预测的分数。失败任务未计入上述收益。

这些配对都满足同一目标容差，但末次误差和动作轨迹不完全相同，允许容差内的精度与用力交换。

## 实际网络与“想象”机制

### 共享身体模型

- 25 个身体节点 + 地面 token + 全局 token；2 层 Transformer，隐藏维度 64、4 个注意力头。
- 节点包含关节状态、电机力矩、地面广义关节负载、连杆位置、接触力／点／标志等；加入由 URDF 计算的连杆方向。
- 质量、惯性、关节轴、连杆偏移和力矩上限作为先验；父子连杆使用软注意力偏置，其他连杆仍可相互影响。
- 全部 24 个关节均可动作，包括头、腕和踝滚转。动作是有界关节目标增量，没有人工“抬头协同”“抬手协同”等动作字典。
- 动力学网络约 74,006 个参数，预测关节跟踪残差、浮动基座平移／转动、接触力、广义关节负载和该段动作的用力／机械功。
- 未来身体点和方向由预测关节／基座状态经过可微 URDF 正运动学得到。没有独立回归一组可能与骨架互相矛盾的身体点，也不把已知 URDF 几何再当成未知知识来学习。

输入为当前状态与动作，输出物理后果。目标不改变同一动作本应产生的物理后果。

### 目标条件注意力

目标为以下数据结构，可同时提供多个目标：

```python
Goal(
    nodes,                 # 身体节点编号
    local_points,          # 所选连杆上的局部点
    target_positions,      # 世界坐标目标
    position_masks,        # 哪些位置分量需要满足
    local_axes,            # 所选连杆上的局部方向轴
    target_directions,     # 世界坐标目标方向
    direction_weights,
)
```

目标策略约 98,561 个参数，通过目标 token 与身体节点的交叉注意力生成 24 个关节动作。由物理探索的实际终点构造 hindsight 目标；训练从未把测试执行的未来状态提供给推理器。

第一版策略几乎不响应目标变化，验证动作敏感度 RMS 为 0.00185。改用显式交叉注意力后，该值为 0.1188，验证损失下降；但正式闭环中仍未独立完成任务。这说明“读取了目标”与“可靠执行目标”是两种不同证据。第一版代码、权重和验证记录保留在 `goal_results/prototype_v1/`。

### 动作想象与执行

学习规划用目标策略、零动作和小幅扰动初始化 4 组候选，在学习动力学上做 24 次梯度优化；每次只执行选中的一段动作，再读取实际反馈。运动学对照用同样的目标损失和优化预算，假设浮动基座固定、关节到达目标角，没有学习到的接触／跟踪残差。

两者的候选初始化不同：学习规划包含目标策略提案，运动学从零动作和扰动开始。因此闭环对照不能隔离“预测模型本身”的贡献；留出预测误差对照则不涉及动作提案。

**正式测试选动作时没有调用未来 MuJoCo 轨迹，没有物理 oracle 筛选，也没有站立 QP 接管。** MuJoCo 用于当前观测和实际执行；训练采集允许克隆状态开展分支探索。

这也是本次与之前“物理校验后成功起身”的区别：之前的起身结果不算入本轮网络控制成功数。

## 数据、分组与冻结规则

- 36 个俯卧／仰卧被动稳定态，每个状态建立 12 个探索锚点，每个锚点分支探索 16 个全关节动作，得到 6,912 对转换。
- 另从之前两条物理搜索起身轨迹抽取 48 个支撑状态，各探索 16 个动作，增加 768 对转换。这部分全部用于训练，并非测试状态，也没有提供手工起身关节参考给策略。
- 总计 7,680 对：训练 5,376、验证 1,152、预测测试 1,152。
- 训练被动种子 200–211；验证 212–214；预测测试 215–217。额外已有起身状态只进入训练。
- 闭环正式测试为新种子 900、901、902，各有俯卧／仰卧两种初态。六个身体区域、两类目标、六种方法，任务矩阵完整执行。
- 有／无显式接触输入分别训练动力学和策略，网络规模、数据和训练预算相同。无接触条件仍有编码器、电机力矩和几何，不能称为完全没有接触线索。
- 动力学训练 35 个 epoch；最终目标策略训练 35 个 epoch。按验证损失选权重，不按正式测试结果挑权重。
- 采集前写下 `GOAL_PROTOCOL.md`，验证阶段的改动有记录。正式测试前冻结控制器、模型、阈值及文件 SHA-256。`reproducibility.json` 确认冻结文件未变。

执行环境中途重启，已完成的单个试验留在磁盘上。`resume_goal_tests.py` 校验冻结文件、复用完整结果，仅补跑缺失试验；没有因为结果不好而重新调参或删除失败。

## 判据与预测指标

动作段持续 0.32 s，物理步长 2 ms，电机命令每 10 ms 更新。总预算 10 段：8 段目标控制，2 段共同的固定关节目标保持，合计 3.2 s。所有方法使用同一保持过程。

抬高目标为所选点的世界高度 +25 mm，水平位置不限制。方向目标将通用选取的身体局部轴朝世界向上方向转动 15°。并非每个区域都可用一个局部关节独立完成，允许全身参与。

最后一段用 16 个间隔 20 ms 的采样点判定：位置有效分量误差均 ≤8 mm、方向误差均 ≤5°、身体点三维速度均 ≤0.04 m/s。未启用的位置／方向分量不计入误差。“末次误差”是最后记录采样点的误差，约在 3.182 s；末态全身指标另在完整 3.2 s 后计算。没有把接近目标但仍在晃动的试验算成功。

| 留出预测指标，0.32 s 时域 | 完整接触输入 | 无显式接触输入 | 固定基座运动学 |
|---|---:|---:|---:|
| 全身体点三维位置 RMSE | 5.95 mm | 6.59 mm | 9.11 mm |
| 头部点三维位置 RMSE | 4.42 mm | 4.26 mm | 4.05 mm |
| 左手点三维位置 RMSE | 7.26 mm | 8.15 mm | 10.90 mm |
| 左脚点三维位置 RMSE | 9.64 mm | 10.13 mm | 16.46 mm |
| 实际接触节点竖直力 RMSE | 13.57 N | 14.19 N | 未预测 |
| 用力积分预测相关系数 | 0.760 | 0.620 | 未预测 |

平均改善主要来自手脚，不包括头部的改善承诺。预测更准也不保证优化后的动作更好：动作优化可能放大模型误差，而且本轮主要是单段预测，尚未形成可靠的长时支撑计划。

## 大目标挑战与未解决的问题

使用相同控制器、相同 Goal 接口，分别从俯卧／仰卧 seed 900 测试三类目标，每次 32 段动作（10.24 s，含同样的末段保持）：

- 基座上的点抬高 80 mm。
- 躯干转正并达到 0.16 m 低位高度。这个条件没有完整定义臀部接触，因此不能仅凭它称为“坐姿”。
- 基座达到名义站立高度、身体方向竖直，同时两足底达到地面并朝向平整；额外检查足部承重。

**六次全部失败。** 本轮没有学会从这些状态坐起或站直。之前物理搜索＋QP 的成功录像是另一个实验，不改变这里的结果。

局部抬高时，脚部任务可能接近高度目标却仍有运动，或者保持阶段失去目标。当前控制主要优化目标点／方向和用力，未显式优化目标点速度、质心动量及多步接触切换。这与观察到的失败相符，但还需要进一步对照才能确定各因素的作用。

下一轮有明确可检验的方向：对所有身体区域继续使用同一接口，按目标距离、保持时间和所需接触变化的难度组织探索；加入动作末端速度及多步身体／接触预测，补采卸载、支撑转移和达标保持的数据。不能仅凭增加注意力层数就假定这些问题会解决。

## 物理范围与检查

使用官方 Pi Plus 24 自由度 URDF，名义质量约 11.0002 kg，浮动基座、平地、重力与接触开启。摩擦 0.8、关节阻尼 0.08、armature 0.003、接触时间常数 0.008 s、电机一阶延迟 15 ms 均沿用实验假设。

关节目标有界，实际电机力矩按 URDF 上限约束。正式试验峰值力矩比例 0.99985；由于驱动力矩包络不等于硬速度限幅，最大速度达到 URDF 数值约 1.19 倍，最大软关节限位穿透约 0.0234 rad。没有外部基座助力、悬挂、焊接或执行中的位姿重设。

感知使用仿真提供的理想基座／关节状态、接触力及 `J.T @ F` 地面广义负载，**没有实现仅靠编码器和电流反演全身接触**。没有地形变化、传感器噪声、未知质量／摩擦或跨机器人测试。

训练已覆盖被测试的身体节点；没有把某个身体部位完全留出训练。共享接口和权重不等于已经证明形成了能迁移到未知部位或另一机器人的抽象身体图式。

检查已覆盖可微几何与 MuJoCo 一致性、用于优化的雅可比与有限差分一致性、分组隔离、非负实测用力／功、实际力矩限幅。四条固定的成功／失败轨迹独立连续复放，状态／电机与用力积分差均为 0，成功判据重新计算一致。检查不能代替任务成功。

```bash
python -m venv .venv
.venv/bin/pip install -r requirements-ground.txt

.venv/bin/python build_model.py
.venv/bin/python goal_checks.py
```

```python

from goal_control import GoalController

world = GoalWorld()

controller = GoalController('efficient')

# 只改节点编号：24 头；17/22 手；6/12 脚；0 基座。
goal = make_goal(world, node=17, kind='lift', amount=0.025)
action, prediction = controller.action(world, goal)
state, measured_cost, trace = world.advance_full(action, trace=True)
```
